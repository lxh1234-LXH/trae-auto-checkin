# trae-auto-checkin

Windows 桌面客户端「自动签到」工具。通过 **模板匹配 + Win32 API 模拟点击**，在每天指定时间自动打开 **TRAEWork** 和 **WorkBuddy** 完成签到 / 领取积分，并注册为 Windows 计划任务长期无人值守运行。

已打包为开箱即用的 `checkin.exe`：**自动找到目标程序、自动适配不同电脑的分辨率与缩放**，不需要改代码，也不需要每个使用者装 Python。

> 适用于只有桌面客户端、没有稳定 API 可调用的签到场景。不注入进程、不修改客户端文件，全部操作都在 UI 层完成。

---

## 特性

| 特性 | 说明 |
| --- | --- |
| **应用自动定位** | 四层兜底依次尝试：手动指定 → 运行中的进程 → 注册表卸载信息 → 常见安装目录 → 开始菜单快捷方式。换任何一台电脑都能自己找到 TRAEWork / WorkBuddy 装在哪 |
| **多尺度模板匹配** | 同一按钮在不同分辨率、不同 DPI 缩放下像素尺寸不同。匹配时会依次尝试 0.5x~2x 共 12 档缩放，找不到就换一档，而不是直接判失败 |
| **校准兜底** | 万一某台电脑上仍然匹配不上，界面上点「校准」即可全屏截图 + 拖框重新裁剪模板，几秒钟解决，不用改代码 |
| **图形化设置** | 双击 exe 打开界面，自己填签到时间（几点几分）、重试间隔、应用路径，不用手写 JSON |
| **绿色版** | 解压即用，配置和模板都放在 exe 同目录；目录只读时自动退回 `%APPDATA%` |
| **区分「已领取」和「真失败」** | 每步执行前先检测「今日已签」标记，命中则判定 `skip` 并跳过，避免重复点击和无意义报错 |
| **抗干扰** | 点击前校验目标窗口是否被其他程序遮挡，被遮挡先重新切前台；锁屏时直接放弃本次执行，交给计划任务稍后重试 |
| **失败留证** | 任何非成功结果都会自动保存全屏截图到 `shots/`，一眼看出卡在哪一步 |

## 快速开始

### 方式一：直接用打包好的 exe

1. 解压 `checkin.zip`，得到 `checkin` 文件夹；
2. 双击 `checkin.exe`，打开设置界面；
3. 确认两个应用都显示「已就绪」（没找到就点「自动检测」或手动「浏览」选 exe）；
4. 填好签到时间（默认 `08:00`），点「注册计划任务」。

之后每天到点会自动签到，不需要再管。

### 方式二：从源码运行

```bash
pip install -r auto-checkin/requirements.txt
cd auto-checkin

python checkin.py            # 打开设置界面
python checkin.py --detect   # 只做路径探测，打印结果
python checkin.py --run      # 立即执行一次签到
```

## 命令行参数

| 参数 | 作用 |
| --- | --- |
| （无参数） | 打开设置界面 |
| `--run` | 执行一次签到（计划任务调用） |
| `--only 名称` | 只跑某个应用，调试用 |
| `--detect` | 只做路径探测并打印结果，不改界面 |
| `--install` | 按 `config.json` 里的时间注册计划任务 |
| `--uninstall` | 删除计划任务 |
| `--status` | 查看今天各应用的结果，以及待校准的模板 |
| `--calibrate [模板名]` | 打开校准向导；不带模板名则列出全部模板状态 |

## 工作原理

```
计划任务触发
      │
      ├─ 锁屏？ ──是──► 退出(code 3)，等下次重试
      │
      ▼
  读 config.json / flows.json / state.json
      │
      ▼
  ┌─ 对每个 App ────────────────────────────────────┐
  │  1. 定位 exe：进程 → 注册表 → 常见目录 → 开始菜单 │
  │  2. 按 进程名 + 窗口标题正则 找窗口               │
  │     找不到 → 用定位到的路径启动并轮询等待          │
  │  3. activate()：Alt 键绕过前台锁定切到最前        │
  │  4. 依次执行 steps[] 里的动作                     │
  │  5. 每个动作前确认窗口未被遮挡                    │
  └─────────────────────────────────────────────────┘
      │
      ▼
  结果 ok / skip / fail → 写回 state.json，失败自动截图
```

### 多尺度匹配

`core.find_template()` 先用模板原尺寸（1.0x）在全屏截图里做归一化互相关，若相似度已很高就直接返回；否则把模板依次缩放到 0.9x / 1.1x / 0.8x / … / 2.0x 再试，取全局最高分。

这样同一套模板可以跨分辨率（1920×1080 / 2560×1440 / 4K）和跨 DPI 缩放（100% / 125% / 150%）使用。程序启动时调用了 `SetProcessDPIAware()`，统一按物理像素计算，避免坐标偏移。

### 应用定位顺序

1. **手动指定** — `config.json` 里填了路径且文件存在，直接用；
2. **运行中的进程** — App 已经开着，直接从进程拿 exe 路径；
3. **注册表卸载信息** — 读 `HKCU/HKLM\...\Uninstall` 的 `DisplayName` / `InstallLocation` / `DisplayIcon`；
4. **常见安装目录** — 按目录名线索在 `%LOCALAPPDATA%\Programs`、`%ProgramFiles%`、各本地磁盘根目录等位置逐层剪枝搜索；
5. **开始菜单快捷方式** — 解析 `.lnk` 的真实目标（通过 `WScript.Shell`，不依赖 pywin32）。

探测到的路径会回写进 `config.json`，下次直接用，不会每次都重新找。

## 计划任务说明

注册的任务名为 `trae-auto-checkin`：

- **触发器 1**：从 `config.json` 指定的时间开始，每天重复；间隔与持续时长同样可配（默认每 30 分钟重试一次，持续 16 小时）。这样即使早上锁屏、关机或前台被全屏程序占用，当天稍后也能自动补跑成功。
- **触发器 2**：用户登录时触发，开机当天不漏签（可在界面上关掉）。
- **动作**：静默启动 `checkin.exe --run`，不弹任何窗口。
- **其他**：`MultipleInstancesPolicy=IgnoreNew` 不重复启动、`StartWhenAvailable=true` 错过计划尽快补、单次超时 15 分钟。

查看任务状态：

```powershell
schtasks /Query /TN trae-auto-checkin /V /FO LIST
```

## 配置说明

`config.json` 是使用者唯一需要关心的文件，界面上改的就是它：

| 字段 | 说明 |
| --- | --- |
| `schedule.time` | 每天几点开始签到，24 小时制 `HH:MM` |
| `schedule.retry_interval_min` | 失败后多久重试一次（分钟），`0` 表示不重试 |
| `schedule.retry_duration_hours` | 重试窗口持续多少小时 |
| `schedule.on_logon` | 登录时是否也补跑一次 |
| `lock_guard` | 锁屏时是否放弃本次执行 |
| `apps.<名称>.enabled` | 是否启用该应用 |
| `apps.<名称>.exe` | 该应用的 exe 路径，留空则自动探测 |

`flows.json` 定义「每个应用长什么样、按什么顺序点哪里」，内置了一套默认值，一般不用动。进阶用户想适配新的客户端可以改这里。可用动作：

| action | 作用 | 关键参数 |
| --- | --- | --- |
| `activate` | 把目标窗口切到前台 | — |
| `wait` | 等待若干秒 | `seconds` |
| `key` | 按键（目前支持 `esc`） | `key` |
| `click_rel` | 以窗口右下角为原点相对点击 | `x`, `y` |
| `open_menu` | 打开可切换的菜单，点一次检测一次，最多试 `tries` 次 | `click{x,y}`, `markers[]`, `threshold`, `tries`, `wait` |
| `skip_if_image` | 命中模板则判定「已处理」并跳过本应用 | `template`, `threshold`, `reason` |
| `click_image` | 命中模板后在其坐标上叠加偏移点击 | `template`, `threshold`, `dx`, `dy`, `on_missing`, `fallback{x,y}` |
| `shot` | 保存一张全屏截图 | — |

执行结果有三种：`ok` 走完全部步骤、`skip` 检测到今日已完成（**不是错误**）、`fail` 出错并自动截图。

## 打包分发

```bat
cd auto-checkin
build.bat
```

输出在 `dist\checkin\`，把整个文件夹压缩后发给别人即可（**必须整个文件夹一起发**，不能只发 exe）。

`build.bat` 会自动剔除用不到的大文件（OpenCV 的视频编解码 DLL、Pythonwin 等），把体积从约 189MB 压到约 153MB。

## 常见问题

**Q：界面显示「未找到」，自动检测也找不到？**

点「浏览」手动选中该应用的 exe 即可。TRAEWork 一般在安装目录下的 `TRAE SOLO CN.exe`，WorkBuddy 一般在 `%LOCALAPPDATA%\Programs\WorkBuddy\WorkBuddy.exe`。

**Q：日志里出现 `未匹配到 xxx.png` 怎么办？**

说明这台电脑上的按钮和内置模板对不上（换了主题、语言或版本）。处理方式：打开 `shots/` 里对应的失败截图，确认按钮的大致位置 → 回到设置界面，找到那一项点「校准」→ 按提示把 App 切到能看到该按钮的界面 → 点确定后 5 秒自动截屏 → 拖动鼠标框选按钮 → 保存。之后就一直用你裁的这张模板。

**Q：为什么会判定 `skip`？**

说明检测到「今日已签 / 今日已领」的标记，属于正常结果，不是错误。

**Q：点击位置偏移了？**

校准一次即可——重新裁剪的模板是基于本机当前分辨率截的，偏移会自然消失。若仍有偏差，可微调 `flows.json` 里对应 `click_image` 的 `dx` / `dy`。

**Q：早上没执行成功，是不是就漏签了？**

不会。重试窗口默认每 30 分钟一次、持续 16 小时，加上「登录时触发」和「错过计划后尽快启动」，当天内一般都能补上。

**Q：校准向导只能在主屏用吗？**

是。校准截取的是主屏，请在主屏上操作。
